最貴的開發,最容易全暴露

節點 08 · Agent 開發的費用 × 暴露陷阱

▶ 看影片 🎓 資安攻防 🎬 13 個段落 🀄 投影片 + 逐字稿
本集開場

所有 AI 用法裡,最花錢的就是 agent 開發。而正因為它最貴,大家最想省錢——偏偏一省錢,就換來一次最大的暴露。這一集就講清楚,這個『貴』跟這個『暴露』,是怎麼綁在一起的,以及你該在哪裡設下那道閘,讓公司能用、又不會把家底一次送出去。

1

這一集:最貴的開發藏最大的陷阱

  • 1agent 開發,是所有用法裡最花錢的
  • 2正因為貴,最誘人去用公開免費版
  • 3一用公開版,就一次暴露最多、最敏感
逐字稿

先把這一集的骨架講清楚。第一,agent 開發是你所有 AI 用法裡,最花錢的那一種。第二,正因為它貴,大家最想省成本,最誘人的就是改用公開的免費版。第三,問題就出在這——agent 開發一用公開版,你等於在一次動作裡,把公司最多、也最敏感的東西,一起送了出去。

2

為什麼 agent 開發吃算力最兇

  • 1它是無限循環:讀、想、做、再讀
  • 2它是入口:所有任務都從它進來
  • 3循環轉越久,算力吃越兇,越花錢
逐字稿

為什麼偏偏是 agent 開發最貴?因為它跟你聊天問一句、答一句不一樣。它是一個無限循環:讀程式、想一步、動一下手、再回頭讀,一圈一圈地轉,直到把任務做完。它又是整個系統的入口,所有任務都要從它進來。循環轉得越久、進來的任務越多,吃的算力就越兇,帳單自然就越高。

3

先看正常:企業版加去敏後開發

逐字稿

先看正常、正確的樣子。你要做一個功能,不是把整包程式塞進去,而是先過一道閘:只留這次真正要碰的那一小塊,再把裡面的真名、真數字、真流程都拔掉。去敏後的片段,才送給企業版的模型端點——企業版的條款寫明不拿你的資料去訓練。模型回建議、你收下,整趟下來,公司的核心資產從頭到尾都沒有出門。先把這幾個角色各自在做什麼記起來。

4

正常裡,夾了一個省錢的小錯

  • 1帳單一來嫌貴,順手換成公開免費版
  • 2公開版條款:你送進去的都可能被訓練
  • 3按下去的當下,功能照跑,你毫無感覺
逐字稿

但正常使用裡,幾乎一定夾著一個小錯。最常見的就是:帳單一來,看到 agent 開發這麼燒錢,順手就把端點換成公開的免費版。公開版跟企業版差在哪?差在條款——你送進去的東西,都可能被拿去訓練。而最麻煩的是,你按下去的那個當下,程式照樣寫得好好的、功能一切正常,你根本不會有任何感覺,完全不知道自己已經踩了雷。

5

錯誤點與結果,隔了很久才爆

逐字稿

這張圖是這一集的靈魂:錯誤點跟結果點,是分開的。你換成公開版、把整包程式丟出去的那一刻,什麼事都沒有;可能隔了很久,那份程式跟規格才真的進了訓練、或者被外洩,結果才爆出來。等資安團隊發現,他們得往回查很久,因為根因遠在好久以前;更慘的是,那份核心資產已經流出去了,暴露收不回來,善後的代價高得嚇人。這道閘,早該設在你按下換版本的那一刻。

6

最貴開發 × 省錢公開版 = 最大暴露

逐字稿

把整條線攤開來看。左邊是最貴的開發——agent 無限循環、吃算力最兇;中間是那個省錢的動作——帳單太高,改用公開免費版;右邊就是後果——整份 codebase 加整份規格書,一次全送給供應商,這就是最大的暴露。而要避免它,不是不開發,是改走下面那條路:功能限縮,或是去敏。最貴的開發,乘上為省錢用公開版,等於一次送出最多、最敏感的東西。

7

到底送了什麼:整包核心資產

  • 1整份 codebase:程式全貌一次過去
  • 2整份規格書:商業邏輯與真實流程
  • 3用 Claude Code 開發,就是送給 Anthropic
逐字稿

那『整包丟』到底丟了什麼,聽起來才夠痛?第一,整份 codebase,你的程式全貌一次全過去。第二,整份規格書,你的商業邏輯、真實流程,公司最值錢的 know-how 都在裡面。舉個具體的:你用 Claude Code 這類工具做開發,就是把這些送給了背後的供應商 Anthropic。這不是抽象的風險,是你最敏感的核心資產。

8

為什麼防火牆、防毒擋不住

  • 1沒有惡意檔、沒有可疑連線
  • 2是工程師自己合法地把資料送出去
  • 3這是『合法使用』,不是一場攻擊
逐字稿

那你現有的防火牆、防毒,為什麼一點反應都沒有?因為這裡沒有惡意檔案、沒有可疑連線、沒有人入侵。從頭到尾,是工程師自己坐在位子上,合法地打開工具、把資料送了出去。傳統防護攔的是『有人打進來』,可是這件事是『我們自己送出去』,是一次百分之百的合法使用。所以那一整套防禦,在這個陷阱面前,幾乎是空的。

9

一個原則:可以用,但不能整包丟

  • 1不是禁止用 agent 開發,能力要拿
  • 2是別把整個專案的鑰匙一次交出去
  • 3守法就兩道閘:功能限縮加去敏
逐字稿

所以結論不是因噎廢食、把 agent 開發禁掉——那個開發能力,公司該拿、也拿得起。真正的原則是一句話:可以用,但不能整包丟。不要因為方便,就把整個專案的鑰匙一次交出去。怎麼做到又用又不整包丟?靠兩道閘:一道叫功能限縮,一道叫去敏。接下來兩張,我們一道一道講。

10

設閘一:功能限縮,只給這次要的那塊

  • 1least privilege:最小權限原則
  • 2只餵這個任務真正要碰的那幾支檔
  • 3不給整個 repo、不給整份規格
逐字稿

第一道閘,叫功能限縮,骨子裡就是資安的最小權限原則,least privilege。意思是:你這次要做哪個功能,就只把那個功能真正會碰到的那幾支檔餵給它,其他一律不給。別因為懶,就把整個 repo、整份規格書一股腦全塞進去。你給它的越少,一旦出事,暴露的也就越少,這一步是在源頭把送出去的量壓到最低。

11

設閘二:去敏,只留機制、不留領域

  • 1拔掉真名、真數字、真實流程
  • 2只留下要解的那個技術結構
  • 3讓它幫你解題,不讓它認得你是誰
逐字稿

第二道閘,叫去敏,核心一句話:只留機制,不留領域。你要 AI 幫的,通常是一個技術結構、一段邏輯;至於裡面的真名、真數字、真實業務流程,那是領域,拔掉就好。把真實資料換成假的、把公司特徵抹掉再餵進去,它照樣幫你把題目解出來,卻認不得你是誰、碰的是哪家公司。解題能力你拿到了,暴露的核心卻留在家裡。

12

接回主軸:止血之外,還有根治

  • 1因在『用公開版整包丟』那一格
  • 2限縮加去敏是止血,把暴露壓小
  • 3根治在節點 12:地端加開源,資料不出門
逐字稿

把它接回整個系列的主軸。我們守因不追果——這一集的因,就在你為了省錢、用公開版還整包丟出去的那一格。功能限縮跟去敏,是很有效的止血,能把暴露的量壓到很小,但它們終究還是把東西送出了門。要根治,得看節點十二講的地端加開源:模型跑在自己家裡,資料從頭到尾都不出門,再大量地開發、再燒算力,也沒有東西被送出去。

13

帶走一句話

  • 1最貴的開發,別用最省的方式送出去
  • 2可以用,但功能限縮加去敏,不整包丟
  • 3要根治:地端加開源,資料永遠留在家
逐字稿

這一集帶走一句話:最貴的那種開發,千萬別用最省錢的方式,把家底一次送出去。agent 開發公司該用,但守住兩道閘——功能限縮,只給這次要的那塊;去敏,拔掉真名真數字真流程,就是不整包丟。而想徹底不再暴露,答案是地端加開源,讓資料永遠留在自己家裡。我們下一站見。
